# context/

The foundation. Five files that everything else reads from.

## Fill them in this order

1. **`business-context.md`** — who you are, what you do, who you sell to. Everything else references it.
2. **`brand-guidelines.md`** — how you look and sound. The voice rules are what stop drift.
3. **`competitors.md`** — you can't position without knowing the alternatives.
4. **`expert-pov.md`** — the beliefs and the one big idea. What makes content sound like a person.
5. **`goals.md`** — what you're aiming for, so work can point at it.

Then update `../CLAUDE.md` with the short version of each, so the spine stays current.

## Rules of thumb

**Keep it short.** A context file nobody reads is worse than no context file. Be specific and cut everything else.

**Date your changes.** Every file has a change log at the bottom. Use it. Knowing something is six months old is more useful than assuming it's current.

**Don't invent.** If you don't know a competitor's pricing, write "unknown" rather than a guess. A context layer built on plausible-sounding filler produces confident, wrong output at scale.

**Refresh on a cadence.** Monthly for the fast-moving parts (competitors, messaging). Quarterly for positioning. Weekly is overkill.

## Why this matters

Without a context layer, every piece of work starts from zero and nothing compounds. With one, a correction you make once becomes a constraint the system keeps.
